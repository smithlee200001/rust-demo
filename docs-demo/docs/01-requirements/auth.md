# Auth 模块需求规格（PRD）

## 1. 目标

提供安全、可扩展的邮箱密码登录与 Refresh Token 轮换机制。

## 2. 核心需求

- **用户注册**：支持邮箱 + 密码注册，密码需满足最低强度校验（至少 8 位，含字母与数字）。
- **用户登录**：校验凭证后签发 Access Token 与 Refresh Token。
- **防暴力破解**：同一 IP / 账号连续失败 5 次后触发 15 分钟冷却。

## 3. 验收标准

- [ ] 正确凭证返回 `200` 及 Token；错误凭证统一返回模糊提示，避免枚举用户。
- [ ] 登出或密码修改后，旧的 Refresh Token 立即失效。
