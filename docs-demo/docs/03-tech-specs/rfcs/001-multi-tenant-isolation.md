# RFC-001：多租户数据隔离统一方案

- **状态**：评审中（In Review）
- **涉及模块**：`auth`、`billing`、所有业务表

## 1. 提案背景

随着业务模块增多，仅靠应用层手写 `WHERE tenant_id = ?` 容易遗漏，存在越权风险。

## 2. 方案对比

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| 独立数据库（Database per Tenant） | 物理隔离最彻底 | 运维与迁移成本极高 |
| 共享库 + PostgreSQL RLS（推荐） | 数据库层兜底隔离，开发心智低 | 需规范连接池会话变量清理 |

## 3. 待确认事项

- 连接池归还连接前，必须执行 `RESET app.current_tenant_id`。
