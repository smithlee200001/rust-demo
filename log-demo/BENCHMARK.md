# 文件日志实测

环境：Linux x86-64 云容器，Intel Xeon Platinum 8573C，Rust 1.99.1，Release 构建，临时文件位于 overlayfs。每组 5 轮，在每轮轮换配置顺序，结果取中位数。每条输入 144 字节（含换行），每条含三种合成用户名路径。每个配置使用新文件。

计时包含文件创建及每文件加密初始化、批量写入、加密收尾并 flush。输入构造、非对称密钥对生成和终端口令输入不计时。文件经过操作系统缓存，不执行 fsync；不代表断电持久化延迟。各列独立取中位数，总耗时不一定等于其他列的中位数之和。

## 怎么读这些数

- **对称加密主要花在开文件。** age 口令模式的 scrypt 每个文件做一次，本机约 1.9–2.0 秒；不是每条日志都做一次。两组对称配置的总耗时波动大于脱敏开销，不能把带脱敏组的总中位数较低解读成脱敏提速。
- **单独看持续写入。** 100,000 条时，明文约 23 ms，非对称约 37 ms，对称约 52 ms；带脱敏后分别约 74、100、108 ms。本测试每条都有三个匹配项，不等于实际应用的负载。
- **自动写日志优先考虑公钥模式。** 写端不需要保存解密私钥，且本机每文件初始化不到 0.3 ms。需要人为输入口令、且每次写一个较长日志时，对称模式仍可用。
- Windows / macOS 尚未实测。应在实际磁盘上运行同一基准，并按真实记录长度、格式及脱敏命中率重测。

## 复跑

在 `log-demo` 目录执行：

```bash
cargo run --locked --release --bin log-file-bench -- --records 10000 --rounds 5
cargo run --locked --release --bin log-file-bench -- --records 100000 --rounds 5
```

默认写入系统临时目录；如果要测特定文件系统，可在启动前把临时目录环境变量指向该文件系统上可写的测试目录。
